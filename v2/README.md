# CMMS - سامانه مدیریت تعمیر و نگهداری

## راه‌اندازی
```bash
npm install
npm install -g @tauri-apps/cli   # یا npx tauri
npm run tauri dev                # حالت توسعه
npm run tauri build              # خروجی نصب‌کننده ویندوز
```

## معماری
- فرانت‌اند: React + Tailwind + Vite
- بک‌اند: Rust (Tauri v2)
- دیتابیس: SQLite (فایل `cmms.db` در AppData) با کتابخانه rusqlite

## ارتباط فرانت و بک‌اند
فرانت با `invoke("نام_کامند", {...})` از `@tauri-apps/api/core` به توابع `#[tauri::command]` در Rust صدا می‌زند.

## مدل دارایی صنعتی (v0.2)
- سلسله‌مراتب ۴ سطحه: Site → System → Equipment → Component (با path مادی و جلوگیری از چرخه)
- طبقه‌بندی ۲۸ کلاس تجهیزات بر اساس ISO 14224 + ماتریس بحرانیت A-D
- مدیریت وضعیت بهره‌برداری، تاریخ کمیسیونینگ، مدارک فنی، مشخصات فنی پویا (JSON)
- سازگاری کامل با داده‌های قبلی: جدول machines از طریق trigger با assets همگام می‌شود

## برنامه‌های PM و Job Plan (v0.3)
- Job Plan: مراحل اجرایی با زمان تخمینی، قطعات پیش‌بینی‌شده، نکات ایمنی و ابزار
- برنامه PM: زمان‌بندی (روز/هفته/ماه/سال) یا کنتوری (ساعت کارکرد/کیلومتر/متر)
- تولید خودکار دستورکار برای برنامه‌های سررسید + زمان‌بندی مجدد خودکار پس از تکمیل

## نسخه نهایی صنعتی (v1.0) — ماژول‌ها
1. داشبورد KPI (MTTR، انطباق PM، ترند، حالت‌های خرابی)
2. تقویم تعمیرات + برنامه‌ریزی منابع (بار تکنسین‌ها)
3. مدل دارایی ISO 14224 (Site→System→Equipment→Component)
4. چک‌لیست روزانه/هفتگی/ماهانه
5. دستورکار با چرخه حیات + تاریخچه وضعیت/فیلد + قطعات مصرفی
6. PM + Job Plan + تولید خودکار دستورکار + زمان‌بندی مجدد
7. انبار (گردش موجودی) + BOM + رزرو
8. RCA (5Why/ماهی/FTA) + CAPA
9. Condition Monitoring + تعمیرات پیش‌بینانه خودکار
10. کاربران/نقش‌ها/تأییدها + Audit Log کامل

## نکات فنی
- ترتیب قفل سراسری: user سپس conn (جلوگیری از ددلاک)
- منطق گارانتی/وضعیت CM در helperهای مشترک نگهداری می‌شود
- machines از طریق trigger با assets همگام است (سازگاری ماژول‌های قدیمی)
